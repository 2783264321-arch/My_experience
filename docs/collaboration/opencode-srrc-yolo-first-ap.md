- **下一步优先做真实预测框上的专家训练/校准，并加未匹配/

关键现象：

1. **幅度专家严重偏向 class11**：argmax 343 个 10→11，只 33 个
   11→10；改坏几乎全是 10→11。AP10 从 0.713 掉到 0.524。
2. **I/Q argmax 方向更平衡**，但置信度中位只有 0.59；0.70 gate
   后只剩 35 个改动，却有 17 个未匹配框。
3. **幅度+相位 ≥0.70 是目前最平衡的规则**：77 个 10→11、
   48 个 11→10；42/14 和 15/0；但仍有 54 个未匹配改动。
4. 未匹配改动占比很高（54/125），所以 AP 增益不能全部归因于
   匹配目标；下一版要单独报告 matched-only 和 unmatched-only。

### 3.1 匹配 / 未匹配拆分（诊断用）

真值匹配只用于分析，不是部署规则。把同一批候选拆成“只改匹配框”
和“只改未匹配框”：

| 专家/规则 | 只改匹配 n | ΔmAP50 | AP10 | AP11 | 只改未匹配 n | ΔmAP50 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 幅度 argmax | 244 | **+0.012 pp** | 0.5817 | 0.7364 | 132 | **−0.471 pp** |
| 幅度 ≥0.70 | 222 | **+0.384 pp** | 0.6244 | 0.7458 | 120 | **−0.428 pp** |

- **所有“只改匹配”都是正 AP**；幅度+相位 ≥0.70 最高 **+0.468 pp**。
- **所有“只改未匹配”都是负 AP**；未匹配改动是当前全量收益的
  主要拖累。
- 因此下一版最直接的改进不是换网络，而是**抑制未匹配/重复框
  改动**：候选需同时满足置信度、预测几何/宽度和去重条件；
  只在有明确匹配证据时才改，或对未匹配框使用更严阈值。

## 4. 效率复盘

- 本轮 654 个候选串行裁剪 **607.96 s**，是主要耗时；
- 三路推理本身很快（GPU 前向），但被串行裁剪拖住；
- `tail` 缓冲导致中途看不到进度；
- 下一版必须：
  - 候选裁剪并行化（4–8 workers）；
  - 每 50 个候选打印进度；
  - 按 `(sample_id, pred_idx)` 缓存候选窗口，三路专家复用；
  - 输出直接写日志文件，不用 `tail` 缓冲；
  - 有卡模式下，先在 CPU 侧并行备好候选缓存，再上 GPU 推理，
    避免 GPU 空等 CPU。

# D-FINE-L SAHI 后处理复核：Soft-NMS 是真实短板

2026-11-26。分支 `work/dfine-sahi-post`，基于 `work/spacenet-first-principles@6223d6a`。
冻结 e25，不训练，只比较粗图/细片候选进入全局合并后的后处理。固定
`val`，未使用 test。

## 0. 结论先行

- **Soft-NMS Gaussian σ=0.5 明显优于原类内 NMS 0.5**：
  `0.765636 / 0.723509` vs `0.761728 / 0.713928`，
  **+0.391 / +0.958 pp**。
- **所有组都为正**：Wi‑Fi20 +0.38、Wi‑Fi40 +0.63、SRRC +0.18、
  窄带 +0.07 pp；14 类逐类 AP 没有一项下降。
- **NMS 0.6/0.7 也有收益，但不如 Soft-NMS**：+0.13/+0.33 和
  +0.09/+0.58 pp；说明问题不是“阈值太严”这么简单，而是硬抑制会
  直接删掉同类重叠的正确框。
- **WBF 0.55 失败**：0.631545/0.571728，合并过度；本实现不保留。
- **判断：把 Soft-NMS Gaussian σ=0.5 作为新的合并候选默认**，
  原 NMS 保留为对照。直接 val 总耗时约 800 s vs 原 NMS 591 s；
  固定候选池上的单次合并已从逐框 `torch.cat` 优化到 **82 s**，
  但端到端仍受两次合并/AP 统计和模型前向影响，需要继续并行化。
- 这是目前第一个**无训练、可复现、全组正收益**的 pipeline 改进。

## 1. 方法

固定 e25 候选池（742,414 个候选，边界/细片过滤后、合并前），比较：

| 变体 | 规则 |
| --- | --- |
| A 原 NMS 0.5 | 类内 NMS IoU 0.5，每样本全局前 100 |
| NMS 0.6 / 0.7 | 只放宽硬 NMS 阈值 |
| Soft-NMS linear | 类内按 `score *= 1−IoU` 衰减，IoU>0.5 |
| **Soft-NMS Gaussian** | 类内按 `score *= exp(−IoU²/σ)` 衰减，σ=0.5 |
| WBF 0.55 | 类内加权框融合，IoU>0.55 |

Soft-NMS 后仍做每样本全局前 100；框坐标不变。当前实现用
`alive` 掩码代替逐框 `torch.cat`，固定候选池单次合并 **82 s**。

## 4. 为什么 Soft-NMS 有效

候选审计已经显示：

- IoU 0.5 时全 query → 合并后只损失 0.4 pp；
- IoU 0.9 损失 5.9 pp，IoU 0.95 损失 8.6 pp；
- 训练集有 133 对同类完全同框标注，硬 NMS 0.5 必然压掉一个。

Soft-NMS 不直接删除重叠候选，而是按 IoU 衰减分数；这保留了
**同类、真实重叠**的正确框，同时仍压低重复框。因此严格 mAP
（高 IoU）收益（+0.96 pp）明显大于 mAP50（+0.39 pp）。

WBF 失败说明：当前实现把不同实例过度融合；不是“融合一定更好”。
Soft-NMS 是更保守、更安全的折中。

## 5. 判断

**建议把 Soft-NMS Gaussian σ=0.5 接入正式合并入口，作为新的默认候选。**
理由：

- 无训练、无新权重，完全复用 e25；
- 全组正收益，14 类无回退；
- 高 IoU 收益明显，直接补上 SAHI 后处理的短板；
- 实现简单，可复现。

保留项：

- 原 NMS 继续作为对照；
- `--merge soft --soft-sigma 0.5` 显式开关，暂不强行改所有历史脚本默认；
- 已把 Soft-NMS 改成掩码向量化实现，固定候选池单次合并 82 s；端到端
  仍约 800 s，主要受两次合并/AP 和模型前向影响，下一步做按样本并行
  或 GPU 合并。

2026-11-23。分支 `work/dfine-query-review`，基于 `main@49e724d`。
按 [三模型复盘与改进方案](dfine-three-model-review.md) 第 6 节第一步，
冻结 D-FINE-L 第 25 轮 `best.pt` 与第 50 轮 `last.pt`，各跑一次
完整 val，复用同一次推理输出比较：

- **原流程**：保留跨类候选，按原规则边界过滤、细片 0–5 过滤、
  全局类内 NMS、每样本前 100；
- **query 去重**：同一视图同一 query 只保留最高分类别，再走同一
  NMS/前 100；
- 额外统计 Wi‑Fi 0–2 真类分数排名和 FM 漏检阶段。

## 0. 结论先行

- 两轮原流程都精确复现既有结果：第 25 轮 mAP50 **0.761728**、
  第 50 轮 **0.723699**；候选数 154,165 / 154,262，推理 361 / 367 s。
- **query 去重明显掉分**：第 25 轮 **0.693540（−6.82 pp）**，
  第 50 轮 **0.666096（−5.76 pp）**；Wi‑Fi20 AP 掉约 **12 pp**，
  SRRC 掉 **8–15 pp**。候选只减少约 6–13%，收益远小于损失。
- **正确类别经常排第二/第三**：Wi‑Fi 0–2 的 GT 上，第 25 轮真类
  rank1/rank2/rank3 = **49.2% / 32.0% / 17.0%**；第 50 轮为
  **46.9% / 26.9% / 15.9%**，还有约 10% 排到 rank4 或更低。
  去重会把第二选择的正确类删掉，所以不是候选合并问题。
- **第 50 轮回落主要是分类/排序，不是框**：定位召回
  0.9844→0.9818、候选数几乎不变；SRRC AP 0.7809→0.6471、
  Wi‑Fi20 0.5513→0.4813，FM 反而 0.6456→0.6595。
- **FM 漏检主要发生在原始候选阶段**：第 25 轮 88 个漏检中
  **80 个 no_raw_candidate**、7 个 NMS/前 100、1 个边界/过滤；
  第 50 轮 82 个漏检中 74 个 no_raw_candidate、7 个 NMS、1 个错类。
  合并阶段不是 FM 的主因。
- **最建议的改动：先做 Wi‑Fi20 `0/1/2` 的组内分类学习/重排，不要
  接 query 去重。** FM 的漏检需要单独补原始候选覆盖；不是这轮
  的首选。

## 4. 判断与最建议的改动

### 4.1 第 50 轮为什么框准但 AP 降

- 定位召回只从 0.9844 降到 0.9818，候选数几乎不变；
- 下降集中在 **SRRC（−13.38 pp）和 Wi‑Fi20（−7.00 pp）**；
- Wi‑Fi20 真类排名从 rank1 49.2% 降到 46.9%，rank4+ 从 1.6%
  升到 9.6%；分数排序/分类变差；
- FM 反而改善；所以不是框退化，是**类别分数和排序退化**。

### 4.2 候选合并还是分类学习

**选分类学习。** query 去重在同一视图内删掉正确第二类，mAP
−5.8 ~ −6.8 pp；候选合并不是当前瓶颈。正确类在 rank2 的比例
约 27–32%，说明模型有信息但没有把真类排到第一。最值得做的是
Wi‑Fi20 `0/1/2` 的组内分类/重排，而不是继续减少候选。

具体建议（下一步只改一个变量）：

- 冻结 D-FINE 特征主体、query 选择和框回归；
- 用第 25 轮权重初始化，在**匹配到 GT 的 Wi‑Fi20 目标**上加入
  `0/1/2` 组内分类监督；
- 同一单通道输入、同一训练样本/采样顺序/学习率/更新步数；
- 先做约 5 轮短训，完整 val 对照原第 25 轮和第 50 轮；
- 重点看 `0/1/2` AP、真类 rank1 比例和严格 mAP，同时回归 SRRC/FM。

**不接 query 去重。** 若未来要减少候选，只应在不损失 rank2 正确类
的前提下做重排/校准，而不是提前删类。

### 4.3 耗时

- 两轮完整 val：**361 s / 367 s**（约 6 分钟/轮），共约 12.1 分钟；
- query 去重、排名和 FM 阶段统计复用同一次前向，没有第二次推理；
  额外后处理在秒级；
- 最终候选从 154k 降到 134k/145k，但 AP 损失远大于时延收益。

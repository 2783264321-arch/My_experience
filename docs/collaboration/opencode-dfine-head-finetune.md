## 0. 结论先行

- 两组都从第 25 轮 `best.pt` 初始化，只训练 `decoder.dec_score_head`

- **control**：mAP50 **0.759040**、mAP50:95 **0.710786**，相对第 25 轮
  **−0.27 / −0.31 pp**。
- **group**：mAP50 **0.759422**、mAP50:95 **0.710689**，相对第 25 轮
  **−0.23 / −0.32 pp**。
- **group 相对 control 没有有效增益**：mAP50 +0.038 pp，mAP50:95
  −0.010 pp；Wi‑Fi20 `0/1/2` 逐类 AP 全部小幅下降（−0.08 / −0.02 /

- **SRRC 相对第 25 轮回退约 1.1 pp**，但 control 与 group 幅度相同
  （−1.13 / −1.05 pp），说明这是 5 轮继续训练带来的漂移，不是组内监督
  额外造成的。**FM 基本持平**（−0.18 / −0.16 pp）。
- 框一致性已核对：24 个样本、416 个视图上，原始 `pred_boxes` 与第 25 轮
  **逐位相同**，最大绝对差 **0.0**；只有分类头参数改变。
- **判断：不值得保留。** group 既没有提高 `0/1/2` AP，也没有改善整体
  mAP 或 SRRC/FM，反而保留第 25 轮更简单、更高。建议回退第 25 轮，
  不再做分类头短训。
- **归一化修正复核（2026-11-24）**：确认旧 `group_loss` 是先按视图取
  均值、再除以总匹配数；改为先对所有匹配目标求和、最后除一次后重跑
  group，结果 **0.759327 / 0.710697**，相对 control 仅
  **+0.029 / −0.009 pp**，`0/1/2` 仍全负。修正了实现错误，但没有带来
  可保留的收益，结论不变。

## 3. 框坐标一致性

- 参数层：两个 checkpoint 中，除 12 个 `decoder.dec_score_head.*`
  张量外，其余参数与第 25 轮**逐位相同**，最大绝对差 **0.0**。
- 输出层：固定 24 个 `val` 样本、416 个视图，逐批比较原始
  `pred_boxes`；两个 arm 都是 `boxes_bitwise_equal=true`，最大绝对差
  **0.0**。分类 logits 最大差 1.72（control）/ 1.66（group），说明变化
  只发生在分类分数。
- 最终候选数只差 52–53 个（154,165 → 154,112/154,113），是分数排序
  改变 NMS/前 100 保留集合导致的预期差异，不是框回归漂移。

## 4. 为什么没有收益

1. **只改线性分类头，改不了 query 特征。** 21,588 参数的线性层只能
   在冻结的 decoder 特征上重新加权；Wi‑Fi20 `0/1/2` 的混淆如果主要
   来自特征不可分，单靠分类头无法修复。
2. **组内 CE 确实优化了，但没有迁移。** 训练集组内损失从 0.62 降到
   0.50，31,889 个匹配 query 的监督量不算少；但验证集 `0/1/2` AP 仍
   低于 control，说明下降不是“没训到”，而是这个目标没有带来更好的
   验证集排序。
3. **原损失与组内 CE 共用同一个头。** 原 D-FINE 分类损失仍在更新
   `0/1/2` 列，两个目标方向不完全一致，组内 CE 的净效果被抵消。
4. **5 轮继续训练本身有漂移。** control 也把 SRRC 拉低 1.13 pp；group
   没有额外加重 SRRC，但也没有恢复。保留第 25 轮比保留任何一组都更稳。
5. **收益量级低于可解释范围。** group 相对 control 的 mAP50 +0.038 pp、
   mAP50:95 −0.010 pp，且 `0/1/2` 三项全负；方向不一致，不能视为增益。

## 5. 建议

**不保留这次改动，回退第 25 轮。**

理由：group 没有提高 Wi‑Fi20 `0/1/2` AP，没有提高整体 mAP，SRRC 与
FM 也不优于第 25 轮；它只增加了训练流程和一次 22 分钟的短训。继续在
分类头上加组内 CE 或延长轮数，是在同一个受限假设上加码，预期收益很低。

如果 Wi‑Fi20 仍是下一阶段重点，只建议再试**一个**不同层面的改动：
在冻结的第 25 轮候选上训练一个轻量 `0/1/2` **候选级重排器**，输入
候选框、分数和上下文特征，输出组内三类概率；重排后再走原 NMS/前 100。
它不修改检测器的框和 query，能把“分类头线性不可分”与“候选特征可用”
分开验证。若重排器在完整 `val` 上不能同时满足 `0/1/2` AP 上升且
mAP50:95 不降，就停止这条线。

## 8. 归一化修正复核（2026-11-24）

### 8.1 确认的问题

在 `49a98d9` 的 `group_loss` 中，每个视图单独调用
`F.cross_entropy(logits, y)`，默认 `reduction="mean"`，然后执行：

```python
total += F.cross_entropy(logits, y)   # 每个视图先取均值
count += len(sel_q)
return total / count
```

实际归一化是：

\[
L_{\text{old}} = \frac{\sum_v \text{mean}_{i \in v}\text{CE}_{v,i}}
{\sum_v n_v}
\]

而不是“所有匹配目标的 CE 求和后除一次总匹配数”：

\[
L_{\text{new}} = \frac{\sum_v \sum_{i \in v}\text{CE}_{v,i}}
{\sum_v n_v}
\]

两者只在每个视图匹配数都为 1 时等价；视图匹配数越多，旧实现越会
低估它的权重。**确认是“先按视图取均值、再除以总匹配数”。**

### 8.2 修正与重跑

- 已改为 `F.cross_entropy(..., reduction="sum")`，每个小批次内先对
  所有匹配目标求和，最后只除一次总匹配数。
- 监督覆盖不变：5 轮仍是 **31,889 个匹配 query**，平均 **8.56 个/步**。
- 组内 loss 均值从 **0.7014** 变为 **0.8712**；这是归一化改变权重后的
  预期结果，不是匹配数或监督量变化。
- 只重跑 group 修正组，control 直接复用；配置仍为第 25 轮初始化、
  `dec_score_head` 21,588 参数、5 轮、4 源 × 累积 2、5e-4、seed 1729。
- 训练 1,334 s，完整 val 586 s；本轮只用 `fit/val`，未跑 test。
- 框一致性：416 个视图上原始 `pred_boxes` 与第 25 轮逐位相同；除
  `dec_score_head` 外参数最大绝对差 0.0。

### 8.4 判断

- **归一化确实有错，修正本身是正确的。** 旧实现会把匹配数少的视图
  相对放大，修正后按每个匹配目标等权。
- **但修正没有带来收益。** 相对 control，mAP50 +0.029 pp、mAP50:95
  −0.009 pp；`0/1/2` 逐类 AP 全部下降（−0.14 / −0.18 / −0.08 pp），
  Wi‑Fi20 组 −0.14 pp；相对旧 group 也基本不变（−0.010 / +0.001 pp）。
- 这不是“没训到”：匹配数、训练轮数、学习率和种子都相同，组内 loss
  也确实优化了；问题仍是线性分类头在冻结特征上的可分性，而不是分母。
- **不保留修正 group，也不保留旧 group；最终仍是第 25 轮。** 本轮没有
  用 test 验证修正版，旧 group 的 test 结果不能直接套到修正版上。
- 如果 Wi‑Fi20 还要继续，仍只建议候选级 `0/1/2` 重排器；不再做分类头
  短训或继续调整 group CE 的归一化。

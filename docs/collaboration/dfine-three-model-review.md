# SpaceNet 三模型复盘与下一轮改进方案

2026-11-23。依据 GitHub `main` 的 `ae35d0d` 版本复核三模型表、训练记录、逐类 AP、混淆矩阵与解码实现。本文中的效果均来自项目固定验证集。逐框预测和权重留在 AutoDL，新增实验为后续方案。 [复核版本](https://github.com/2783264321-arch/My_experience/commit/ae35d0d)

## 1. 现阶段怎么定主线

**保留粗图＋细片，把 D-FINE-L 第 25 轮作为新的准确率对照。** 同一套单通道功率图、粗细片和验证口径下，D-FINE-L 达到 **0.761728 mAP@0.5**。相对 YOLO11s 提高 **11.20 个百分点**，相对 YOLO26l 提高 **10.21 个百分点**。在更严格的 `mAP@0.5:0.95` 下，D-FINE-L 相对 YOLO26l 提高 **11.61 个百分点**。最扎实的变化是框更准、漏掉的目标更少。宽带 Wi-Fi 和 SRRC 的类别识别也有改善。 [三模型同口径复评](https://github.com/2783264321-arch/My_experience/blob/ae35d0d/reports/detector_upgrade/three_model_comparison.md)

**质量改进优先看 Wi-Fi 20 MHz 的分数排序和调制错类。** 这组 997 个标注，D-FINE-L 已框中 991 个，按匹配框计，只有 499 个判对类别。先用现有权重看正确类别出现在哪一步。如果它已经是同一候选的第二选择，可查排序和重复输出。如果检测器几乎总给它低分，优先改分类学习。 [第 25 轮逐类结果及混淆矩阵](https://github.com/2783264321-arch/My_experience/blob/ae35d0d/reports/detector_upgrade/formal_dfine_val_history.json)

YOLO11s 保留作低成本参照和粗细片消融的原始载体，YOLO26l 保留作现代 YOLO 对照。局部 IQ 专家暂时收尾。官方 `test` 继续封存。

### 本轮统一了哪些条件

- **数据和表示。** 固定 fit 5,957 个 IQ 文件，val 1,543 个文件、7,162 个标注。IQ 经 0.7 ms 单窗 STFT 得到 `F×512`，在频率方向聚合一张全频粗图并截取多张细片。每个视图以单通道功率表示输入，形状为 `1×2048×512`，2048 是频率行、512 是时间列。
- **取片和评测。** 每轮每个 fit 样本训练一张粗图和一张轮转细片。val 用全部 24,975 张粗细视图。回映原采样的时频坐标后，沿用细片边界扣留、细片类 `0–5` 过滤、每类 IoU 0.5 的全局 NMS 和每样本最多 100 个输出。正式复评的分数门槛为 0.001，每视图候选上限为 300。
- **模型适配。** YOLO11s 使用既有 C1 DirectReg。YOLO26l 和 D-FINE-L 适配单通道首层及 14 类输出。D-FINE-L 使用 `dfine_l_obj2coco_e25.pth` 初始化，补了矩形位置编码，并按 `2048×512` 生成对应位置缓存。三者共享输入和全局评测规则，保留各自训练损失、模型解码器和预训练初始化。YOLO26l、D-FINE-L 物理 batch 为 8 视图，累积 2 步。YOLO11s 的原训练是 16 视图物理 batch。
- **权重与可比性。** YOLO26l 和 D-FINE-L 按过滤 mAP@0.5 选择最佳 EMA 权重，再做完整复评。YOLO11s 采用已有的修正权重。现有记录为同一验证划分下的单次正式训练，`val` 也参与了权重选择。表里的差值回答「换成这套已训练的检测器，整条流程获得多少收益」。若论文要把收益归到某个具体模块，需要单独控制预训练、其他模型结构、损失和训练策略。

### D-FINE-L 赢在哪里

1. **漏框少，精框多。** YOLO11s、YOLO26l、D-FINE-L 分别匹配到 6,860、6,861、7,050 个标注。对比 YOLO26l，D-FINE-L 多覆盖 189 个，未匹配数从 301 降到 112，类无关 AP75 提高 5.35 个百分点。在三个模型都框中的同一批 6,742 个目标上，平均 IoU 依次为 **0.9324 / 0.9382 / 0.9612**。这就把「框到了更多目标」和「同一个目标框得更准」两件事都量出来了。
2. **错类有改善，整体准确率容易掩盖分组差异。** 同一批 6,742 个目标上，分类正确率为 **84.74% / 85.43% / 86.27%**。相对 YOLO26l，D-FINE-L 在共同匹配的 Wi-Fi 0–5 上由 50.44% 到 53.81%，在 SRRC 10/11 上由 65.22% 到 68.26%。LoRa/AM/FM 则由 98.45% 到 98.29%，而同一批框的 IoU 由 0.9072 到 0.9377，这一组的提升证据主要在定位。
3. **优势在无细片类别过滤时也在。** D-FINE-L 第 25 轮无过滤为 0.760426，加过滤为 0.761728，变化仅 +0.13 个百分点。YOLO26l 无过滤为 0.652208，两者在无过滤下仍相差 +10.82 个百分点。D-FINE 原论文的分布式边框逐级细化与本轮精定位现象相符，当前三模型表能直接支持的是整个系统的收益。

### 4.3 候选量和后处理值得测，先把实际影响量出来

D-FINE-L 最佳权重最终输出 154,165 个候选，距整个 val 的 154,300 个上限只差 135 个，平均每个样本 99.91 个。YOLO26l 为 47,236 个，平均 30.61 个。D-FINE 的官方解码是在「候选框 × 类别」的分数中取前 300 项，同一个 query 生成的同一个框可以带多个类别。项目 YOLO 路径每个框先选最高分的类别，全局 NMS 又是同类之间去重，因此 D-FINE 的不同类重复假设仍可能留在输出中。这些假设也可能保留正确类别。候选数先用来找拥挤发生在哪一步，保留或合并以实测 AP、漏检和时延为准。 [上游 D-FINE 解码](https://github.com/Peterande/D-FINE/blob/956d170/src/zoo/dfine/postprocessor.py) · [项目公共合并](https://github.com/2783264321-arch/My_experience/blob/ae35d0d/scripts/detector_upgrade/validate_dual.py)

## 6. 下一轮按三个交付物推进

### 第一步交付一张真实 AP 表，顺便解释末轮回落

冻结 D-FINE-L 第 25 和第 50 轮。两个权重各完整跑一次 val，保留粗细来源、query 编号、回映框、分数和少量相关类别排序信息。已有最终框缓存用来复现原分，query 级对照需要保留合并前信息。按当前运行记录，两次完整验证的推理与既有评测约 20 分钟，额外记录和分析单独计时。以下对照合在同一轮，不为每项单独启动实验。

| 同轮输出 | 怎么比较 | 回答的问题 |
| --- | --- | --- |
| 原流程 | 重现两个权重在全 val 的 mAP、逐类 AP、召回和最终候选数，沿同一批匹配目标比两轮类分数 | 末轮下降集中在哪些真实样本，哪些变化发生在类别分数或合并环节？ |
| 单 query 保留一个标签 | 从原来的候选中，在边界处理和细片类别过滤以后，同一视图同一 query 只保留最高分项，再照原规则 NMS 和取前 100 | 少了跨类重复候选后，整套 AP 和 FM 召回是涨是降？如果正确标签本来排在第二，减少候选会失去它，这个代价也要量出来。 |
| 固定框的类别诊断 | 对 `0–2` 已匹配且判为该组的预测框做真值改类对照，保留原框、原分数和原合并结果。另记同一候选真类排第 1、第 2 的比例 | 这批错类在现有框和分数下对 AP 有多少影响？真类常排第二，还是模型分数已经把它排得很低？真值是分析工具，实际部署看前一行的真实输出。 |

一张表同时给出 mAP@0.5、mAP@0.5:0.95、Wi-Fi 20/40 MHz 各类、SRRC、FM AP 与召回，以及最终候选数和运行时间。按 IQ 文件配对估计差值的区间，尤其是较小的改进。FM 补一列漏检发生阶段。把原始结果、反例和可复现命令写回共享目录，以完整 AP 表作为本步停点。

### 第二步只改一个关键变量，直接回完整验证集

- **若减少候选竞争就带来净收益**，把它接进统一推理入口，核对它是否既改善 Wi-Fi AP，又保住严格 IoU、SRRC 和 FM。低延迟方向也可记录相同召回下的候选量与时延。
- **若主要是同带宽小类本身判错**，首选在 D-FINE 原有分类输出上做一次受控短训。以第 25 轮同一权重启动两组，冻结特征主体、查询选择和框回归分支。对照保留原分类损失，改动组只在与 GT 匹配的 Wi-Fi 20 MHz 目标上加入 `0/1/2` 的组内分类监督。沿用同一单通道输入、训练样本、采样顺序、学习率和更新次数。可先预算每组约 5 轮，用统一完整 val 对比原参考和两个短训组，核对改进是否针对类 0/1。若原生小类分数在现有特征上普遍缺少区分，再考虑更有针对性的表征对照。
- **若第一步表明漏框对目标指标更重要**，优先针对 FM 的实际漏检阶段修改一次，保留同带宽 Wi-Fi 报表作回归核验。例如若有框在合并阶段被截掉，就验证那个环节；若连前段候选都缺失，就使用漏检集中条件设计细片覆盖改动。

选择一个方向推进。合格的结果应能回答「哪些信号变好了，哪些变差，整条 pipeline 的 AP 增益是否值得新增的耗时」。挑一次明显结果做复验，低成本路线保留 YOLO11s，对精度敏感用 D-FINE-L。YOLO26l 继续用于说明重型 YOLO 与跨架构方案之间的取舍。

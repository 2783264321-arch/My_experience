# OpenCode 结果：2048 点复数粗图与 0.7 ms 复数细片的坐标/通道核查

依据 `docs/collaboration/README.md` 的「当前路线」和「复数 STFT 粗图前端
验证」。本轮只做前端小样本核查，不训练检测器，不改原始 IQ/JSON；对照仍是
filtered full val **0.649725**，test 继续封存。

## 1. 核查范围

选 14 个 fit 样本，覆盖 20/40/80 MHz 观测带宽和 20/40/150 ms 时长；每个
样本至少有一个 ≥20 MHz 宽带信号和一个窄带信号，共 76 个 GT 实例。对每个
样本实际读取 IQ，计算：

- 现有 0.7 ms 原生复数 STFT：`F×512`，`h=ceil(N/511)`，右补到 `511h`，
  `center=True`，周期 Hann，双边，fftshift；
- 稀疏 2048 点复数 STFT：`2048×512`，同一 `h`、同一补边和帧中心；
- 稠密 2048 点复数 STFT：`hop=min(1024,max(256,h/2))`，再功率池化和
  相位对齐复数池化到 512 列；
- 0.7 ms 复数 STFT 的频率池化：矩形和 Hann 两种 2048 带；
- 20/80 MHz 合成单音，用于相位/幅度标定。

复数使用现有 PSD 尺度 `Z/sqrt(Fs·sum(w²))`；另外报告相干尺度
`Z/sum(w)`。14 个样本上，细片 `|Z|²` 与现有 `stft_power_fast` 的最大相对
误差为 **4.3e-7**，说明功率路径一致。

## 2. 时频坐标：时间可共享，频率只是同一全局坐标

**时间轴：可以精确共享。** 两种视图都用 `h=ceil(N/511)`、
`n_ext=511h`、`center=True`，得到相同的 512 个帧中心
`t_j=j·h/Fs`。稀疏 2048 正好 512 列；实测最大帧中心差 **0**。

**频率轴：全局物理坐标可共享，但 bin 中心不同。** 两者都能用
`y=(f-f_lo)/B` 映射标签，但：

| 观测 B | 细片 F | 细片格距 | 粗图 2048 格距 | F/2048 |
| ---: | ---: | ---: | ---: | ---: |
| 20 MHz | 14,000 | 1.429 kHz | 9.766 kHz | 6.84 |
| 40 MHz | 28,000 | 1.429 kHz | 19.531 kHz | 13.67 |
| 80 MHz | 56,000 | 1.429 kHz | 39.063 kHz | 27.34 |

粗图一行不等于细片一行；粗图是 2048 行覆盖全带，细片是 2048 行覆盖约
2.93 MHz，并带每片起点偏移。网络必须知道视图类型和频率 scale/offset。
粗图边缘半格量化是 4.9/9.8/19.5 kHz（20/40/80 MHz），相对 20/40 MHz 框
很小，但比细片 0.71 kHz 半格大很多。

## 3. 通道定义：必须做帧中心相位校正，幅度尺度要分开

原始 STFT 相位含一个与 **bin 频率 × 窗半长** 有关的项。2048 点和
0.7 ms 的窗长不同，所以 raw Re/Im 不在同一相位参考上。合成单音
20 MHz / 2 MHz 的最近粗 bin 是 2.001953 MHz（偏 0.2 bin），raw 相位与细片
相差 **π**（粗系数为负实数）；这不是信号属性。

统一乘以帧中心校正：

```text
Z_ref[k,j] = Z[k,j] · exp(+j·2π·f_k·(L/2)/Fs)
```

后，同一单音在 20 MHz 的相位差降到 **1e-8 rad**，80 MHz 为 3e-9 rad；
边缘列 j=0/511 仍有少量泄漏。这个校正应作为粗/细共用 Re/Im 通道定义的
前提。

**幅度尺度：** PSD 归一化让 `|Z|²` 是功率谱密度，但单音峰值随窗长变化。
80 MHz/5 MHz 时粗图峰值 0.00558、细片 0.02916（比值 0.191 =
sqrt(2048/56000)）；相干归一化 `Z/sum(w)` 两者都是 **1.34986**。20 MHz
单音偏 0.2 粗 bin，相干幅度 1.315 vs 1.350（低 2.6%，是窗泄漏）。

建议：

- 功率分支继续用 `Z/sqrt(Fs·sum(w²))`，与现有 `|Z|²` 功率完全对齐；
- Re/Im 分支用 `Z/sum(w)` + 帧中心相位校正，使不同窗长的单音幅度可比；
- 若必须共用一个张量，用 PSD 加一个在 fit 上冻结的 per-view 固定 scale，
  不要声称 raw PSD Re/Im 幅度天然相等。

## 4. 长样本短窗空档：影响细节，不主要影响边界

2048 点窗在 80 MHz 只有 25.6 µs。相对 512 列间距，GT 信号时段被短窗覆盖
的比例实测：

| B/T | 稀疏覆盖率 |
| ---: | ---: |
| 20 MHz / 20 ms | 1.000 |
| 80 MHz / 20 ms | 0.654 |
| 40 MHz / 40 ms | 0.654 |
| 20 MHz / 150 ms | 0.349 |
| 40 MHz / 150 ms | 0.174 |
| 80 MHz / 150 ms | **0.087** |

注意这是**每列积分时间**的比例，不是“列缺失”的比例。每个列仍有短窗，
连续信号在每列都亮；检测器看到的是 512 列，不是空洞。真实影响是快照
方差和列内细节丢失。

76 个 GT 实例实测：

- 稀疏/稠密功率比中位数 **0.998**（范围 0.687–1.042），连续信号的中心
  快照基本是无偏能量估计；
- 漏检 bin（稠密 bin 能量 >5×稀疏）**157 / 38,912 = 0.40%**，最差
  **12.1%**，出现在 20 MHz/150 ms 的突发窄带信号；连续 WiFi 不是最差群；
- 边界误差（10% 峰值阈值）在 20/40 ms 中位数 **0.039 ms**，150 ms
  **0.294 ms**（约一列），p90 2.94 ms；稠密功率和 0.7 ms 细片的 p90 相同。
  也就是说边界误差主要由 512 列网格和信号强度决定，不由短窗空档决定；
  短窗在时间上其实比 0.7 ms 更锐，列间距 `h` 才是边界量化。

数据集最小 GT 时长是 4 ms，远大于 150 ms 下的列间距 0.294 ms，所以一个
完整标注信号不可能整体落进空档；风险是内部短突发/断点，而不是整框丢失。

结论：长样本空档不会整体漏掉连续信号，也不会显著破坏框边界；但 2048 点窗
在 80 MHz 约 2 个 WiFi OFDM 符号，远少于 0.7 ms 的约 55 个符号，不能替代
细片做调制细节。突发窄带信号在 150 ms 下可丢 6–12% 的 bin，需要更密的
粗图或细片兜底。

## 5. 开销

RTX 4090 主机实测，单位秒/样本；池化是 Python 循环，未优化：

| B/T | 细片 0.7 ms | 稀疏 2048 | 稠密 2048 | 稠密池化 | 细片频率池化/Hann |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 80/150 | 0.444 | 0.049 | 0.408 | 0.561 | 0.098 |
| 40/150 | 0.209 | 0.030 | 0.199 | 0.471 | 0.095 |
| 20/150 | 0.089 | 0.006 | 0.086 | 0.293 | 0.076 |
| 80/20 | 0.367 | 0.005 | 0.027 | 0.244 | 0.101 |
| 20/20 | 0.096 | 0.004 | 0.011 | 0.233 | 0.076 |

细片固定 512 个长 FFT，开销近似与 T 无关。稀疏 2048 很便宜。稠密 2048 +
功率池化在 80/150 约 **0.95 s**，与细片同量级或略高；20/150 约 0.38 s。
细片频率池化约 0.1 s。GPU/向量化池化可降低池化项，但不会降低 FFT 项。

## 6. 复数池化的相干性

对每个 GT 频带/时段，相干度 `|mean z|² / mean|z|²`（1=保功率，0=完全相消）：

| 粗图复数构造 | 中位数 | p10 | p90 |
| --- | ---: | ---: | ---: |
| 稀疏 2048，不池化 | 1.000 | 1.000 | 1.000 |
| 稠密 2048，相位对齐复数池化 | 0.222 | 0.058 | 0.661 |
| 0.7 ms，矩形频率池化 | 0.184 | 0.094 | 0.352 |
| 0.7 ms，单带 Hann 池化 | 0.303 | 0.150 | 0.591 |

宽带信号做相干复数池化会损失 70–80% 功率，这是物理相消，不是数值 bug。
功率池化保能量，应该用于能量/上下文；稀疏 2048 保复数功率但有时间空档。
单带 Hann 还有带边界零点：合成单音正好在边界时 Hann 幅度 0.00075（细片
1.35），矩形也会被相邻带分走（0.075）。所以复数粗带需要 **50% 重叠的
滤波器组**，不能只用单带 Hann 或矩形。

## 7. 判断与建议

**能否共享？** 时间轴：可以精确共享。频率：只能共享全局物理/归一化坐标，
不能共享 bin 中心（粗图比细片粗 6.8–27.3 倍）。通道：可以共享，但必须做
帧中心相位校正，并明确“功率用 PSD、Re/Im 用相干幅度”或冻结 per-view
scale；否则相位会差 π，幅度也会随窗长变化。

**长样本空档：** 对连续 WiFi，边界和检测没有灾难性影响；稀疏/稠密能量比
约 1，漏 bin 0.4%，边界中位数一列。对突发窄带，150 ms 下可丢 6–12% bin；
25.6 µs 快照也不能承载 0.7 ms 的调制细节。稀疏 2048 可作为便宜的定位/
上下文视图，不能作为所有类唯一的粗图。

**更好的构造：**

1. **首选复数粗图**：保留现有 0.7 ms 复数 STFT，加 **50% 重叠
   sqrt-Hann/RRC 频率滤波器组** 形成 2048 个复数带，再做帧中心相位校正。
   物理依据：与细片同一时间原子、100% 时间覆盖、共同相位参考，重叠带
   避免单带 Hann 的边界零点。代价：一次细片 STFT（已有）+ O(F·512) 池化，
   约 0.1 s/样本，不需要额外 2048 点 STFT。最小对照：矩形 vs 单带 Hann vs
   50% 重叠滤波器组，检查带中心/边界单音响应、复数相干度和检测 AP。
2. **首选无空档功率粗图**：稠密 2048 点 STFT（hop ≤ h/2）+ 功率池化到
   512 列，保能量、100% 时间覆盖；80/150 约 0.95 s/样本，和细片同量级。
   最小对照：稀疏 2048 功率 vs 稠密 2048 功率 vs 现有 0.7 ms 功率粗图。
3. **不建议**把稀疏 2048 当作唯一粗图，也不建议把单带矩形/Hann 复数池化
   当作能量视图。稀疏保复数功率但 80/150 只有 8.7% duty；相干池化损失
   70–80% 宽带功率。

**下一步：** 先做前端控制，不跑完整训练。同一 512 网格和标签上比较
(a) 现有 0.7 ms 功率粗图，(b) 稠密 2048 功率池化，(c) 0.7 ms 50% 重叠
复数粗图；用冻结或小检测器、现有验证口径测 AP/边界。若采用复数粗图，
Re/Im 用相干归一化 + 相位校正，功率分支保持 PSD。test 继续封存。

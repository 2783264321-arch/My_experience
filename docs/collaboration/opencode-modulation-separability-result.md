# OpenCode 结果：0/1/2 与 3/4/5 的调制可分性（粗图功率 / 局部细功率 / 局部复数 STFT）

依据 `docs/collaboration/README.md` 与 2026-11-18 的“转向调制可分性”要求。
完整检测对照仍是共享 fine-0-5 过滤完整 val **0.649725**（AP_agn 0.905977，
R_agn 0.957833，n_pred 47,784）。test 继续封存。

## 1. 先核对类别 ID 与 Wi-Fi 标签定义

AutoDL 包里的 JSON 只有数字 `class`，没有类别名文件。用公开 SpaceNet
advanced schema 与 SpaceNet/EMSpec 词表核对后，14 类映射是确定的：

| id | 类别 | 标称带宽 |
| ---: | --- | ---: |
| 0 | WIFI 20MHz QPSK | 20 MHz |
| 1 | WIFI 20MHz 16QAM | 20 MHz |
| 2 | WIFI 20MHz 64QAM | 20 MHz |
| 3 | WIFI 40MHz QPSK | 40 MHz |
| 4 | WIFI 40MHz 16QAM | 40 MHz |
| 5 | WIFI 40MHz 64QAM | 40 MHz |
| 6 | BLE LE1M | 1 MHz |
| 7 | BLE LE2M | 2 MHz |
| 8 | Zigbee | 2 MHz |
| 9 | LoRa 250KHZ | 0.25 MHz |
| 10 | SRRC QPSK | 10 MHz |
| 11 | SRRC 16QAM | 10 MHz |
| 12 | AM | 0.1–0.2 MHz |
| 13 | FM | 0.1–0.2 MHz |

本地数据也支持这个口径：0–2 的标签带宽全部精确为 20.000 MHz，3–5 全部精确
为 40.000 MHz；6 约 1 MHz，7/8 约 2 MHz，9 中位数 0.25 MHz，10/11 中位数
10 MHz，12/13 约 0.1–0.2 MHz（6–13 为标称/中位数，实例有变化）。

**Wi-Fi 标签定义：** 0–5 不是六个协议，而是
`20/40 MHz 带宽 × QPSK/16QAM/64QAM` 的六个 WiFi6 组合。因此 0/1/2 是
20 MHz 内的三分类，3/4/5 是 40 MHz 内的三分类；2↔3 是带宽变化，不是调制
变化，本轮不做跨带宽混淆。详细核对：
`reports/spaceNet_class_ids_and_wifi_labels.md`。

## 2. 实验口径

- 冻结 `best_corrected.pt`，复用同一批粗图候选框。
- 每个 `(sample_id, GT box)` 只保留最高分候选，要求 IoU ≥ 0.75：
  **3,754 crops / 2,503 samples**；IoU 中位数 0.984。
- 类别 0/1/2/3/4/5 = 705/716/732/530/517/554。
- 共享按 IQ 样本划分：20% holdout，seed 1729；
  **2,996 train crops / 2,002 samples**，**758 holdout crops / 501 samples**。
  所有表示、两个带宽组、所有 seed 用同一划分。
- 重叠条件：WiFi-clean 1,913；WiFi overlap 1,841；跨类 WiFi overlap 1,604；
  同类 overlap 405；强 WiFi overlap（≥25% 面积）1,513；任意信号 overlap
  3,393，any-clean 361。

三种表示使用同一批框、同一 10% 物理 context、同一 128×256 网格：

- `coarse`：现有 0.7 ms 粗图功率，全带 2048 行聚合后再裁块。
- `local_power`：局部 0.1 ms 复数 STFT，局部频带 -> log power。
- `local_complex`：**同一批复数系数、同一网格**的实部/虚部；去掉全局相位，
  每 crop 联合 RMS 归一化。

0.1 ms 的选择：10 kHz 频率格，约 8 个 WiFi OFDM 符号周期，兼顾频率细节与
时间定位。另做了 0.05/0.2/0.35/0.7 ms 的局部细功率窗长敏感性检查。

## 3. 训练预算

20 epoch 明显欠拟合（coarse 012 train acc ~0.55，holdout 0.403；local power
012 train acc ~0.51），不能用于比较。主比较统一改为 **100 epoch**，
同架构深度/宽度、AdamW lr 1e-3、weight decay 1e-4、cosine、batch 64、
class weights；coarse 与 local power 用 3 个 seed（1729/1730/1731），
real/imag 用 1 个 seed（它 train acc ~99.9%、holdout 已到随机，增加 seed
不改变结论）。

注意：同一个 fit holdout 也用于排除 20 epoch 和选择 0.1 ms 窗长，因此主表
3 seed 数字带有选择偏差，只用于表示方向的 go/no-go，不是最终测试；完整 val
仍是未见过的检查。

| local_complex | 345 | 0.4107（1 seed） | 0.3954 | `[[39,9,44],[25,24,66],[27,17,68]]` |

逐类 recall：

- coarse 012：0.389 / 0.345 / 0.491；local power 012：0.459 / 0.383 / 0.453；
  complex 012：0.371 / 0.338 / 0.338。
- coarse 345：0.721 / 0.487 / 0.482；local power 345：0.681 / 0.577 / 0.500；
  complex 345：0.424 / 0.209 / 0.607。

**局部细功率是唯一正收益**：相对 coarse，012 **+2.28 pp**，345 **+2.72 pp**。
按 seed 配对差值：012 **+2.3 ± 1.6 pp**，345 **+2.7 ± 2.8 pp**；3 个 seed 下
只能算“有希望”，还不能算锁定提升。**实部/虚部双通道明显失败**：012 比
coarse 低 6.0 pp，345 低 14.2 pp；train acc ~99.9%，是记住了训练集的相位
模式，而不是学到调制。

## 5. 窗长敏感性

单 seed（1729）、100 epoch、同一划分，只比较局部细功率；0.1 ms 的主结果是
3 seed。

| 局部窗长 (ms) | 012 acc | 345 acc | 均值 |
| ---: | ---: | ---: | ---: |
| 0.05 | 0.4214 | 0.5893 | 0.5054 |
| **0.10** | **0.4487** | **0.5862** | **0.5175** |
| 0.20 | 0.4442 | 0.5172 | 0.4807 |
| 0.35 | 0.4510 | 0.5204 | 0.4857 |
| 0.70 | 0.4032 | 0.5047 | 0.4540 |

0.1 ms 是两组最均衡的窗长：0.35 ms 在 012 上高 0.23 pp，但 345 低 6.6 pp；
0.05 ms 在 345 上高 0.31 pp，但 012 低 2.7 pp；0.2/0.7 ms 在 345 上明显更差。
因此主比较用 0.1 ms，而不是只挑某一组的最优点。

## 6. 重叠条件

| 表示 | 组 | clean WiFi | WiFi overlap | 跨类 WiFi | 强 WiFi ≥25% |
| --- | --- | ---: | ---: | ---: | ---: |
| coarse | 012 | 0.4354 (222) | 0.3810 (217) | 0.3979 (191) | 0.3752 (183) |
| **local_power** | **012** | 0.4144 (222) | **0.4485 (217)** | **0.4520 (191)** | **0.4444 (183)** |
| local_complex | 012 | 0.3514 (222) | 0.3456 (217) | 0.3351 (191) | 0.3443 (183) |
| coarse | 345 | 0.5915 (173) | 0.5068 (146) | 0.5076 (132) | 0.4720 (113) |
| **local_power** | **345** | **0.6262 (173)** | **0.5251 (146)** | **0.5202 (132)** | **0.5162 (113)** |
| local_complex | 345 | 0.4277 (173) | 0.3904 (146) | 0.3636 (132) | 0.3717 (113) |

局部细功率的收益不是 clean 子集假象：012 在 clean 上略低 2.1 pp，但在
WiFi overlap 上 **+6.8 pp**、强 overlap **+6.9 pp**；345 在 clean、overlap、
跨类、强 overlap 上都更好（分别 +3.5/+1.8/+1.3/+4.4 pp）。这符合“细功率
保留了粗图聚合抹掉的调制/边缘细节，且在另一 WiFi 信号存在时更有用”的解释。

## 7. 判断与下一步

**结论先行：不推进 real/imag 双通道；优先做固定输入的更强检测器/分类器
对照，局部细功率作为该对照的候选输入。**

**不推进实部/虚部双通道表示。** 同一批框、同一批复数系数、同一网格、同一
训练预算下，real/imag 训练集 ~99.9%、holdout 0.349/0.411，已到随机；
这不是覆盖或路由问题。复值网络、相位增强或相位不变特征可以另做，但普通
两通道 real/imag 不是可用方案。

**正信号是局部细功率，不是双通道复数。** 它比 coarse 高约 2.3–2.7 pp，
并在重叠条件下更好；但增益不大、seed 方差约 1.7–2.1 pp，且小 CNN 仍过拟合
（train ~99.9%），所以它是候选，不是已锁定的提升。

**建议优先做固定输入的更强检测器/分类器对照，而不是先做双通道。** 用同一批
proposal、同一共享样本划分、同一 128×256 网格，比较更强固定输入模型
（ResNet18/ConvNeXt-Tiny 1 通道，或检测器 P5/ROI 特征）在 **coarse vs 局部
细功率** 上的表现：

- 若强模型在 coarse 上追平局部细功率，说明瓶颈是容量，保留当前输入、
  先加强检测器/分类器；
- 若局部细功率仍领先，再集成**单通道局部细功率**分支（不是 real/imag），
  然后对 0.649725 跑一组完整 val。

本轮没有再加局部 IQ/星座图检查：短窗 sweep 与 real/imag 已经说明，单纯把
局部相位喂给小 CNN 不够；若强固定输入对照仍失败，下一步应做局部
IQ/星座图或循环特征分类器，而不是继续加宽 STFT 裁块。

本轮不锁表示、不跑完整 val；对照仍是 0.649725。test 继续封存。

## 1. 复核发现：`gt_idx` 是全局编号

`adaptation_pairs.json` 的 `gt_idx` 最大 **7,157**，而 val 只有
1,543 个样本——它是**跨样本的全局 GT 编号**。原脚本
`other_signal_risk` 把它当成**单样本内下标**，因此几乎从不排除
目标本身，导致：

- 目标自己也被算成“另一条信号”；
- `other_frac≈1.0` 的假高重叠；
- 14 个“改对”被误判为“专家类别=其他信号”。

修正方式：

1. 用 `pair.sample_idx` 与 yolo cache 的 `gt_offsets` 计算
   `local_idx = gt_idx − gt_offsets[sample_idx]`；
2. 用该 local idx 从 JSON 取目标信号，核对
   `class / start_frequency / end_frequency / start_time / end_time`
   和 cache GT 几何（atol=2e-4）；
3. 用稳定的 `signal_id` 排除目标，而不是用全局编号/枚举下标；
4. 只用已有最佳短段的 `best_t1/best_t2` 重算 Pred/GT 框重叠。

修正脚本：`scripts/baseline3wifi_sync_diag_recheck.py`；原脚本的
`other_signal_risk` 也已改为按 `signal_id` 排除目标。

## 4. 目标 vs 其他信号

| Pred 框 42 个找回样本 | `ca7e9b0` 旧口径 | 更正后 |
| --- | ---: | ---: |
| 高其他信号重叠（`other_frac≥0.5`） | 42/42 | **8/42** |
| 专家类别 = 其他信号类别 | 30/42 | **4/42** |
| “改对”中专家 = 其他信号 | 14/14 | **0/14** |
| “改错”中专家 = 其他信号 | 1/7 | **3/7** |

修正后：

- Pred 找回 42 段中，只有 **8 段** (`other_frac≥0.5`) 与另一条
  标注信号高重叠（旧口径误报 42/42）。
- 42 段中 **4 段**专家类别等于另一条信号类别；旧口径误报 30/42。
- **14 个改对中 0 个**专家类别等于另一条信号；旧口径误报 14/14。
  其中 2 个改对段与另一条信号高重叠，但类别不同；不能仅凭重叠
  就判定捕获。
- **7 个改错中 3 个**专家类别等于另一条信号——风险仍存在，但不
  是“短段主要在捡其他信号”。

因此上一版“短段主要捡另一条信号”的结论**被推翻**。更准确的
表述是：短段确实能在部分失败框里找到可恢复结构，且多数改对
不能归因于其他信号；但高重叠风险仍有 8/42，不能忽略。GT 框
重复同一模式（8/41 高重叠、3/41 专家=其他信号），说明不是
Pred 框几何独有的问题。

## 5. 这轮能说明什么

1. **短段能通过同步**：42/267（15.7%）Pred 失败框找回
   40,835 符号；class4/5 约 11–12%，class3 对照约 31.5%。
2. **通过后不一定稳定改善目标分类**：整体 +7，但
   adaptation-train +7、calibration-dev 0；class3 对照 −3；
   class4 +2、class5 +8。整体 p=0.189，证据不足以改规则。
3. **不是主要捡其他信号**：修正后 0/14 改对与其他信号同类；
   但 8/42 高重叠、3/7 改错与其他信号同类，风险真实存在。
4. **建议**：保留现行整段规则；不接回推理、不调阈值；本轮收尾。
   短段保留为待验证线索，若以后有更多独立开发数据，再做预注册
   复核；当前不扩大、不进入 final-dev/test。

## 6. 限制

- 只诊断、未改推理/权重；只用 dev 两划分；final-dev/test 未用。
- 修正后找回样本仍只有 42 个（cal 7 个），统计功效很低。
- 2 ms/1 ms/20 段是预注册选择，未扫其他段长。
- 重叠按标称带宽矩形（`fc±bw/2, t1..t2`）计算，不裁到采集带
  边，也未模拟 `1.02×` bandlimit 与 5% edge rolloff；这与 v1
  口径一致，只改了目标排除。它是风险证据，不能证明信号级捕获。
- 未匹配候选只有 12 个，只有 1 个找回；不能估计全量。
